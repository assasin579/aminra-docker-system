# J1/J2 automated technical acceptance

## Acceptance denominator

Use the retained18technical criteria (`J1-A01`–`J1-A08`, `J2-A01`–`J2-A06`,
`X-A01`–`X-A04`). Historical verdicts from2026-10-30 are not copied into a new
run. `j1j2-manifest.json` lists required executable cases and DB regressions;
`scripts/uat/j1j2.py` computes the result from actual run evidence.

A criterion is Pass only when all its required evidence passed. Missing cases,
missing parameter branches, missing runtime proof or changed test source block
acceptance. A failed or flaky test never becomes Pass through another layer's
success. The full174-control/journey baseline remains a separate gate.

## Execute

```bash
# Once per locked Playwright version, if this cache lacks browser binaries:
cd frontend/aminra-web
PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/aminra-uat-browsers" npx playwright install chromium
cd ../..

python3 scripts/uat/run.py --suite j1j2
```

The runner checks browser availability before provisioning containers. No new
npm dependency is required. Optional `--browser-cache`, `--backend-image`,
`--frontend-image`, `--output`, and schema-source flags are described by `--help`.
It creates its own Keycloak realm, app-role PostgreSQL, FE/BE and loopback ports.
The only live schema-source operations are SELECT head and schema-only pg_dump.
No production identities, customer rows, migrations or deployments are changed.

Outputs:

- `j1j2-acceptance.html/json/csv`: the18criteria and every required evidence item.
- `playwright.json` / `browser-report/`: real browser/API case results and artifacts.
- `database.xml` / `database.log`:31shipped PostgreSQL integration cases, run as
  `aminra_app` against the disposable schema and synthetic records.
- `runtime-checks.json`, `db-role.json`, `guard_055.log`, `guard_057.log`: guarded
  downgrade refusals, preserved schema, runtime role and source-image identity.
- `recovery/`: actual post-restore browser login, old/new HTTP file SHA256,
  delivery-audit checks and all three original command-receipt replays.

Exit0means the selected J1/J2 technical gate passed. It does not mean the entire
UAT baseline passed, independent QA/CB signed off, or pilot deployment is approved.

The current dossier UI displays attached count/version, not an attached filename
list. Reuse acceptance therefore checks the selected exact ID in the real request
and receipt, both dossier API references, and the updated UI attachment count.
It does not invent a filename label absent from the product contract.

The history UI compares the latest round to the current packet. The first-round
diff is checked before round2; after round2, immutable snapshots and retained
responses are checked. It does not assert that the UI renders two simultaneous
comparison regions, which is not its existing contract.

Keycloak is the identity source of truth. A DB-only suspension fixture can be
reconciled back from an active token. The suspension case changes only the
isolated realm, validates a genuine suspended-status claim, disables login and
invalidates sessions. It does **not** claim immediate cryptographic revocation
of previously issued active offline JWTs before their expiration. Assignment
revocation is checked with the existing token. The test realm enables imported
custom attributes for its real token mappers; production Keycloak is untouched.

## Limits

The full baseline's complaint/conflict UI failures remain recorded in the prior
expanded run and are outside the selected J1/J2 suite. Eight commercial groups
remain owner-Excluded for this UAT. This suite does not certify physical iPhone,
installed-service-worker/offline, real LLM/SMTP, full certificate issuance,
RLS/forced-RLS, live Vault policy or whole-system disaster recovery. Existing
Keycloak and file storage remain intact during synthetic PostgreSQL recovery.

No workflow or scheduler is enabled. Source remains reviewable separately from
application release. Do not deploy test-only fixture/control mechanisms as an
application API.
